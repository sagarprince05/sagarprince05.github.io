# Prince Sagar — Portfolio

Personal portfolio site. Hand-coded in HTML, CSS and vanilla JavaScript — no build step, no frameworks, no trackers.

Live at **https://sagarprince05.github.io**

## Files

```
index.html                       Home: hero, skills, projects, experience, contact
projects/
  ai-data-assistant.html         Project detail — AI data assistant (Slack bot)
  approval-automation.html       Project detail — approval workflow automation
  price-intelligence.html        Project detail — price intelligence pipeline
styles.css                       Design tokens (:root) + all layout
script.js                        Mobile nav, active nav, scroll reveal, copy email
assets/
  favicon.svg                    "P" mark
  prince.webp                    Portrait cut-out (generated by tools/make_photo.py)
  resume.pdf                     Résumé
  og.png                         1200×630 social preview image
tools/                           Local image-generation helpers (not used at runtime)
```

## Run locally

Open `index.html` in a browser, or serve the folder:

```bash
python -m http.server 4173
```

then visit http://localhost:4173.

## Editing

| What | Where |
|---|---|
| Name, title, blurb, photo | `index.html` → `<section class="hero">` |
| Skills | `index.html` → `<section id="skills">` — add `class="key"` to a tag to highlight it |
| Project cards | `index.html` → `<section id="work">` — duplicate a `.work-card` |
| Project detail pages | `projects/*.html` — copy one, then link it from a card |
| Experience / education | `index.html` → `<section id="background">` |
| Contact email | `index.html` → `mailto:` link, `data-email`, and the JSON-LD block in `<head>` |
| Colours | `styles.css` → `--accent`, `--blue`, `--aurora` and the surface tokens in `:root` |

Asset URLs carry a `?v=` query string for cache-busting — bump it after changing `styles.css` or `script.js`.

## Content policy

This site describes work done during an internship at a high level only. It deliberately contains **no** employer-internal URLs, product codenames, screenshots of internal tools, database schemas, customer or employee names, or company operational figures.

Keep it that way when adding new content: describe the problem, your contribution, the technologies and the outcome — not the internals.

## Deploy

GitHub Pages serves `main` from the repository root; a push goes live in under a minute.

## Regenerating images

```bash
PORTRAIT_SRC=path/to/photo.jpg python tools/make_photo.py   # portrait cut-out
python tools/make_og.py                                      # 1200×630 social preview
```
