Humyn Watcher — AI-powered Slack data assistant

A production Slack bot that lets a team ask questions about live company operations data in plain English (or Hinglish, typos and all) and get accurate, verified answers in ~3 seconds — running 24/7 on a completely free cloud stack (Cloudflare Workers + Groq LLMs + Supabase Postgres) at zero infrastructure cost.

Overview

Anyone on the team can @mention the bot or DM it a question like "how many Akai cameras do we have?" or "top 3 most active operators this week" — even with spelling mistakes or mixed Hindi-English — and the bot writes the SQL, queries the company's Postgres database in real time, and replies in the Slack thread with the answer plus a receipt showing exactly what it searched.

The problem

Operations data (projects, workers, assets, task events) lived in a Postgres database that only technical people could query. Everyone else had to ask around or wait. The goal: instant self-serve answers inside Slack, with strict accuracy — the bot must never invent data — and a hard constraint of zero budget (free tiers only).

Architecture

  • Slack Events API → Cloudflare Worker. A serverless HTTP endpoint verifies every request with Slack's HMAC signature, deduplicates retries, and enforces an admin-managed allowlist so only approved teammates can use the bot.
  • Text-to-SQL with Groq LLMs. A large reasoning model (gpt-oss-120b) converts the question into a read-only SQL query, guided by a hand-built data dictionary of the schema's quirks and team vocabulary. A smaller model handles conversational phrasing, with automatic fallback chains across models when one is rate-limited or retired.
  • Supabase Postgres via Cloudflare Hyperdrive. Connection pooling between the edge and the database, using a dedicated read-only role locked to a single schema with a statement timeout — so the bot can never modify or leak data outside its scope.
  • Cloudflare KV. Stores per-thread conversation memory (so follow-ups like "why?" work), the user allowlist, a 15-minute auto-refreshing schema cache, and an overflow queue for burst traffic.
  • Cron triggers. Drain the overflow queue and keep the bot's knowledge of the database current with no manual updates.

Key features

  • Ask anything, any way — tolerant of typos, broken grammar and Hinglish; always answers in English.
  • Self-correcting SQL — on a database error it retries with the error message; on zero rows it reinterprets the question once (users' vocabulary rarely matches database enum values).
  • Never hallucinates — company-data answers come only from real query results; every answer carries a _searched: …_ or _query: …_ receipt so users can verify what was checked. If the database is unreachable, the bot says so honestly instead of guessing.
  • Deterministic numbers — single-value answers (counts, totals) bypass the language model entirely, so a number can never be garbled in phrasing.
  • Conversation memory — threads remember context, so follow-up questions work naturally.
  • Live knowledge layer — admins can teach the bot new terms and verified queries directly from Slack (define, teach) with no redeploy; taught SQL is test-run before it's saved.
  • Self-updating — the schema, enum values and live project list refresh automatically every 15 minutes; the bot discovered 9 newly added projects and a workforce jump from ~2,800 to ~4,200 workers with zero manual changes.
  • Burst-proof on free tiers — a model-fallback chain plus a KV-backed overflow queue absorbed 12 simultaneous questions and 20 rapid-fire questions in testing with zero failures, despite per-model free-tier token limits.

Engineering challenges solved

  • Direct Postgres connections from edge workers hit subrequest limits — solved with Hyperdrive and by diagnosing a double-pooling conflict between Hyperdrive and Supabase's transaction pooler.
  • Groq retired two production models overnight with no notice — the bot recovered via automatic 404/rate-limit fallbacks; the incident led to a resilient multi-model chain.
  • Early versions occasionally fabricated data when the database path failed — fixed with layered anti-fabrication guards (honest failure replies, receipts on every answer, deterministic rendering of results).
  • Timezone bugs, messy free-text data and schema traps (columns that are always NULL, brand names hidden in variant fields) — all captured as rules in a living data dictionary that grows every time a wrong answer is reported.

Results

  • ~3 second median answer time, end to end.
  • ₹0 / month infrastructure cost — entirely on Cloudflare, Groq and Supabase free tiers.
  • 24/7 availability — fully serverless, no laptop or server to keep running.
  • Serving live data across 30+ project sites, ~4,200 workers and 75,000+ audit events, with accuracy that improves continuously through a screenshot-feedback loop.
